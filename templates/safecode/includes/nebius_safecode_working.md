# How work goes

Read the code here, then change it here with SuperEdit: the sandbox is where it runs, not where it is written. Start from an image with the language version the project supports; its packaging or CI configuration says which, and an image that is too new wastes the first runs. `mcp__contree__rsync` the workspace and install the project's dependencies on a lane from that `directory_state_id` with `disposable: false`; run from `lane:<name>` afterwards so nothing is installed twice. For a bug, reproduce it in the sandbox before changing the code, so the same command can later show it fixed. Then loop: edit locally, `rsync` again, `run` the build or the tests on `lane:<name>` with the new `directory_state_id` and `disposable: true`, read the result, edit locally again. Change files inside the sandbox only for throw-away experiments; what should stay is written here. Finish with WorkspaceDiff and say exactly which sandbox runs proved what.
